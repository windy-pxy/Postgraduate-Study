# 双链规范

链接表示可解释的语义关系，不是图谱装饰。每条关联应能回答“为什么这两篇笔记有关”。禁止为了增加图谱连线而创建无意义链接。

## 目标与命名

优先使用 vault 相对路径、不带 .md 的双链，形式为 `[[目录/笔记标题|显示名称]]`；显示名称可以中文。标题重名时不得依赖短链接猜测目标。章节链接必须指向真实章节索引页，不能指向目录或虚构尚不存在的文件。

链接笔记前先确认目标存在。知识点名尚未确认、目标尚未建立或关系存疑时，先在 [[00-System/Review-Queue|待审核列表]] 写普通文本，不创建悬空双链。模板里的 `[[{{knowledge_note_path}}]]` 仅为占位示意。

## 七类语义关系

- 知识点 → 知识点：在“前置知识”“关联知识”分别记录依赖或可比较的关系，并写一句理由；不能把两个都属于同一科目当成直接关系。
- 错题 → 知识点：knowledge_points 与“关联知识点”指向导致错误或决定解法的知识；错误原因必须来自真实作答证据。
- 真题 → 章节与知识点：chapter 记录资料中真实章节名称或章节页双链；knowledge_points 记录实际考查点。不同教材章节不同，须说明资料版本。
- 资料笔记 → 原始来源：source_file 保存项目相对路径，source_name 与 source_page 保存可核对来源。原始文件在 vault 外，不能伪装成 Obsidian 内部双链；需要打开原件时手动按路径定位，程序不修改原件。正文写清原件页码、必要的文件页序号与摘录范围。
- 薄弱点 → 错题证据：在“证据”链接真实错题、阶段测试或真题作答记录；出现次数只能根据真实记录统计，不能由链接数或猜测生成。
- 阶段测试 → 错题与薄弱点：在错误分布和薄弱点小节链接具体证据；未分析完的结果标记为待审核。
- 学习记录 → 当日实际笔记：记录真实学习内容、新增错题和复习活动，计划与已经完成的活动分开写。

## AI 后续更新边界

AI 只能在资料或笔记提供明确语义依据时建议或添加双链；更新正式笔记前应核对 id、目标、Git 状态和引用来源。无法确定的关系放入待审核列表，不推断“已经掌握”，不补造页码或作答记录。来源引用须包含文件/资料名及原始页码。每个知识声明与个人理解分别标注，不把个人理解充当资料原文。

Obsidian 会显示反向链接，无需为了双向可见在两篇正文重复添加同一句链接。对确有必要的反向关联，可在另一篇中记录其独立语义。

## 工具边界

验证器检查双链与嵌入的文件目标，支持显示别名及标题/块引用中的文件部分；目前不核验标题或块锚点是否存在，也不判断学科关系真伪。相对上级路径、绝对路径、跨库路径不允许作为内部双链。外部普通 Markdown 链接不属于内部双链检查；来源路径由 source_file 单独核对。
